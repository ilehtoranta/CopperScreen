# HD floppy support — 2026-10-18

Lightweight models fitted DD and HD 3.5-inch drives independently of inserted
media. `FloppyDriveCount` still connects DF0–DF3, defaulting to one DD drive.
`FloppyDriveTypes = [LightweightFloppyDriveType.HighDensity]` fits an HD DF0;
unspecified connected entries remain DD. Drive types are fixed at construction.
The desktop exposes each connected drive's DD/HD selection in **Settings >
Floppy Drives > Drive Configuration**. Changing a type requires restarting the
Amiga. Personal profiles and the remembered last machine store all four entries
as `machine.floppyDriveTypes`, for example `["HD", "DD", "DD", "HD"]`.
Older profiles default to DD; omitted list entries also default to DD. A drive's
saved type survives disconnecting and reconnecting it. An HD insertion into a
running DD mechanism is rejected before ejecting existing media, with a message
to select HD and restart.

The runner accepts repeatable `--drive-type <unit> DD|HD` options. Units are
zero-based, types are case-insensitive, and unspecified units remain DD.
For example, `--drives 2 --drive-type 0 HD --drive-type 1 DD --disk hd.adf`
fits an HD DF0 and DD DF1. Options may precede or follow `--drives`; referring
to a disconnected unit is an error. Explicit selections are printed in the
runner output. These options select mechanisms and do not infer a drive type
from mounted media.

HD mechanisms accept 880 KiB DD and 1760 KiB HD sector ADF/ADZ. A DD mechanism
rejects HD attachment before replacing existing media. Both formats have 80
cylinders, two heads and 512-byte sectors. HD has 22 sectors per track and runs
at nominal 150 RPM (400 ms/revolution); DD has 11 and runs at 300 RPM (200 ms),
including in an HD mechanism. The HD encoded track and gap are twice the DD
length, retaining the existing Paula cell rate and integer CCK schedule.
Selection and head changes preserve spindle phase; CIA-B FLAG receives index
at the media's spindle deadline. Write wrap and export use the current track's
cell/sector count. Every dirty HD track must decode all 22 checksum-valid
sectors before export. Existing DD encoding/order and the preserved DD receiver
remain unchanged. Whole-disk preserved-track decoding remains DD.

With the motor off, select edges serialize raw READY bits. A selected motor
on/off cycle resets the sequence, and following selections present MSB first.
HD media returns `DRT_150RPM` (`$AAAAAAAA`); DD media and empty HD mechanisms
return `DRT_AMIGA` (`$00000000`). Original internal DD drives retain their
absent ID circuit; external DD drives identify as before. The SDK raw IDs and
motor/select sequence are reproduced in
[Amiga Test Kit's hardware probe](https://github.com/keirf/amiga-stuff/blob/master/testkit/floppy.c#L193-L218).
The older HRM ID table disagrees with the SDK and physical probe; the raw input
bits are not inverted. WinUAE's
[drive_settype_id implementation](https://github.com/tonioni/WinUAE/blob/master/disk.cpp)
also records the A3000T HD mechanism's media-dependent identification.

## Validation

- Release CopperScreen solution build succeeds with zero warnings/errors in
  `artifacts/hd-production-build`. Normal desktop output copying was blocked by
  the running app; its process was left intact. CopperStart Release solution
  build also succeeds using its existing dependency outputs.
- 34 focused drive/DMA cases pass, including HD writes/export on all four units,
  DD/HD/empty identification, unchanged cell rate and doubled revolution length.
  A subsequent nine-case HD run adds two explicit CIA FLAG deadline cases,
  covering two successive revolutions at each density.
- The engine suite passes 1,258 cases; seven optional native-ROM/media cases
  are skipped and are unavailable coverage. This suite run precedes the two
  additional CIA deadline cases, which pass separately.
- All 77 CopperDisk host tests pass, including HD sector 21, final-track
  round-trip, decoded writeback/cache invalidation, and read-only HD ADZ.
- CopperStart's full 512 KiB ROM passes 11 new HD cases and seven DD regressions.
  HD cases execute native trackdisk through Exec from reset, covering geometry,
  `DRIVE3_5_150RPM`, four physical units, head/cylinder boundaries, offsets beyond
  DD capacity, the final HD sector, and protected-write rejection. All four
  write cases compare the entire exported medium against expected bytes,
  including untouched sectors. A fresh machine boots an independent DD loader
  and reads the saved, unchanged HD medium on DF1. These are full-ROM/media
  replays, separate from the earlier compiled MC68000 protocol fixture.

The ROM is the previous qualified FixedPoint production image, SHA-256
`A02369F8DF572CFC29F01E2A745B05CECB06CC6D2256F399A69998B406D34683`.
Every recorded ROM producer/compiler/CPU input stays frozen. The replay helper
permits replacement only of the emulator assembly when its exact SHA-256 is
explicitly supplied through `COPPERSTART_REPLAY_ENGINE_SHA256`; the original
manifest is preserved. Tested engine SHA-256:
`DFA36EEC23EA6F1760152D368310B504667B152C479D52B0EEA6D3BF28E56E53`.
Tested CopperDisk SHA-256:
`296BEEED06677B7A39488A9543B9755C705ADAABCE79E0296DF51569D1DE584F`.
ROM/media hashes, individual write receipts, exported synthetic media and TRX
results are retained under CopperStart's ignored
`artifacts/hd-emulator-20261018`; engine and disk TRX files are in their test
projects' ignored `TestResults` directories. No ROM or medium is source content.

This qualifies the bounded ideal-ADF model and native driver together. The
chosen 500 ms ready delay, insertion phase, coast-down, analog splice drift,
physical HD hardware and HD preserved/flux formats remain unqualified. The
existing DD preserved-media behavior is retained. No formal throughput
measurement or broad Kickstart HD filesystem qualification is claimed.

cases, including eight new cases for saved types, older/partial profiles,
invalid types, independent clones, remembered disconnected drives, startup,
restart and rejecting HD swaps into an active DD drive. Five optional cases

explicit DD, option ordering, invalid/missing values and disconnected units.
Both HD exports match every byte of the supplied synthetic image. Inputs,
outputs and runner hash are retained under ignored `artifacts/hd-settings-cli`.
The Release solution builds in `artifacts/hd-settings-build` without replacing
the running desktop app's locked output files. Minimal disk boot retains its
DD-only medium restriction; choose a native ROM for HD booting.

## CopperStart HD filesystem replay

The subsequent [OFS/FFS full-ROM validation](../../../CopperStart/Docs/NativeHdFileSystemValidation.md)
passes ten HD cases and four DD regressions on the newer qualified
`6B958D78...F4D57C7D3` ROM and its frozen producer/runtime inputs. Both
filesystems boot startup commands and read upper-half files, including
37,377-byte extension-table reads. FFS mutation/metadata and extension growth
survive 22-sector MFM export and three fresh protected boots, with new blocks
forced above the DD boundary and independent allocation/checksum checks.
The suite performs 17 reset-ROM boots; 31 host filesystem cases pass separately.
This uses the normal hires framebuffer and reports no unsupported engine
features. Physical-drive timing, active-mount media replacement, other native
ROMs and later working-tree filesystem changes remain outside that image's
qualification. Exact hashes, results and limitations are in the linked record.
