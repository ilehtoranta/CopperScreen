# A500+ / native Kickstart 2.04

The `a500-plus-ecs-pal` profile now selects native Kickstart 2.04 (512 KiB,
v37.175), AccurateM68000, the existing PAL 8375 (318069-10) Agnus model with
1 MiB Chip RAM, ECS 8373 Denise, no slow/Fast RAM, RTC and one DD floppy drive.
This reuses the existing ECS implementation; it does not add or qualify a new
physical Agnus revision. The obsolete profile's CopperStart 2.x shim is removed.
The NTSC profile remains unsupported and is not changed by this work.

The app accepts the ROM as a file or a ZIP entry, preserves 2.04 through saved
profiles, recent-session restoration and the existing ECS machine controls,
and identifies it correctly in the ROM picker. Native 2.05 revisions are not
silently accepted as 2.04. Existing explicit 1.3/3.1 source checks and the A1200
3.0 ROM requirement remain intact. The start-menu choices/layout are unchanged;
ROM guidance includes the newly supported version.

Use the existing profile mechanism or command line:

```powershell
dotnet CopperScreen.dll --profile a500-plus-ecs-pal --rom '<your Kickstart 2.04 ROM or ZIP>'
dotnet CopperScreen.dll --profile a500-plus-ecs-pal --rom '<your Kickstart 2.04 ROM or ZIP>' '<your Workbench 2.04 ADF or ZIP>'
```

The first command starts with an empty drive. New media remain read-only by
default. ROMs and Workbench are user supplied and are not part of this repository.
The launcher continues to identify this hardware using its existing
"Amiga 500 with ECS" choice until the separately requested menu redesign.

## Verification

`Kickstart204Tests` separates synthetic ROM/configuration checks from optional
native ROM/media execution. The native cases use the normal
`CopperScreenLightweightSession`, verify native Exec startup and 1 MiB Chip RAM,
and capture both cold boot and reset with and without the supplied Workbench disk.
The supplied Workbench disk first runs an interactive keymap selection script.
The replay waits for the reviewed native prompt, sends `0` and Return through
ordinary keyboard input, then verifies the complete desktop framebuffer. This
declines copying a keymap from Extras and does not change the source disk. Both
the insert-disk screen and the desktop have reviewed pixel hashes; reaching
Exec or the keymap question alone is not a successful desktop boot.
`SavedA500PlusStartsWithoutADiskAndKeeps204InTheExistingLauncher` checks the real
Avalonia launcher with a synthetic ROM; it is not native boot evidence.

```powershell
$env:COPPERSCREEN_KICKSTART204_ROM = '<ROM or ZIP>'
$env:COPPERSCREEN_WORKBENCH204_ADF = '<ADF or ZIP>'
$env:COPPERSCREEN_KICKSTART204_CAPTURE = '<local artifact directory>'
dotnet test CopperScreen.Lightweight.Tests/CopperScreen.Lightweight.Tests.csproj -c Release --filter FullyQualifiedName~Kickstart204Tests
```

The supplied files are opened read-only. Captures and test receipts remain under
ignored `artifacts/a500plus-ks204-20261021/`. A separate artifacts output directory
is used for builds when the running app/Visual Studio locks ordinary binaries.
No emulator timing, CPU implementation, package version or installed app changes
are part of this work. HDF, shared-folder and general software compatibility on
2.04 require separate native coverage.

### Recorded results

- Release production solution build: zero warnings/errors, using
  `dotnet build CopperScreen.slnx -c Release --artifacts-path artifacts/a500plus-solution-build`.
- Host checks: 38 focused ROM/version/machine-preset cases and a separate run of
  123 settings/profile/memory cases pass with no skips. These runs overlap;
  their counts must not be added as a unique-test total.
- Desktop checks: the saved A500+ empty-drive launcher case and both existing
  first-layout cases pass (3/3, no skips).
- Native execution: both empty-drive and Workbench cases pass, each on cold
  boot and reset (2 cases, 4 boots). The unchanged original Workbench disk reaches
  its desktop with Ram Disk and Workbench2.0 icons after declining keymap setup.
  Native Exec reports 1,048,576 bytes of Chip RAM; no session fault or dirty disk
  is observed. This is normal app-session execution, not installed-package,
  audio/performance acceptance or broad Workbench application qualification.
- Final `Kickstart204Tests` run with the reviewed screen hashes enforced:
  11/11 pass, no skips (9 synthetic/configuration cases and 2 native cases).
- No separate compiled-MC68000 probe was added or run; the native cases execute
  the supplied ROM and Workbench binaries. No CPU/chipset implementation changed.
