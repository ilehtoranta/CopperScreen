# 020 CopperHDF boot instruction coverage — 2026-09-27

The indexed-JSR blocker found during [Fast RAM validation](FAST_RAM_2026-09-27.md)
is resolved. Experimental 68020 and 68EC020 now complete the supplied Kickstart
1.3 / Workbench 1.3 CopperHDF boot, including native Fast RAM allocation and OFS
file write/read. This is bounded compatibility evidence, not complete CPU or
filesystem conformance. The [machine-readable record](COPPERHDF_020_2026-09-27.json)
binds source, package, locks, inputs, tests and native captures by hash.

## Cause and correction

The first stop was `$4EB2 $0000` at `$FC4E28`: `JSR (0,A2,D0.W)`.
The advanced CPU interpreter lacked the address-register indexed form even
though its PC-relative counterpart existed. The call must calculate its target
before changing A7, push the address after the extension word, and preserve
condition codes. This also failed with Fast RAM disabled.

Following that call exposed 13 further missing operand forms on the same native
startup and file-I/O path. Copper68k now handles the following forms, for all
register selections encoded by their addressing modes:

| Instruction | Added operand form |
| --- | --- |
| JSR, JMP | Brief indexed address-register target |
| ADD.L | PC-relative displacement source to Dn |
| SUBA.L | PC-relative displacement source to An |
| MOVE.B | Address displacement source to indexed destination |
| ANDI.L, NOT.L | Address displacement destination |
| ADDA.W | Address register source to address register |
| MOVEA.W | Address displacement and PC-relative brief-indexed sources |
| MOVE.B | Address displacement source to predecrement destination |
| ADD.B | Postincrement source to Dn |
| CMPI.B | Predecrement destination |
| MOVEM.L | PC-relative displacement source to register list |

The implementation stays in CopperMod's Copper68k owner checkout, commit
`21c24293d80840bbd892818de6436de4d7e7c290`. No ROM, media, chipset or HDF-device
behavior is patched to bypass these instructions. Architectural expectations use
the instruction and addressing definitions in Motorola's
[M68000 family programmer's reference](https://www.nxp.com/docs/en/reference-manual/M68000PRM.pdf).
Timing follows the existing bounded accelerator policy; it is not a measurement
of a physical 020 accelerator.

The 189 new cases cover signed word/long indexes, scaling, extension-word PC
bases (including MOVEM's preceding register mask), A7 base/index aliasing,
JSR/RTS round trips, byte stack alignment, operand widths, flags, preserved
memory, MOVEM order/masks and unsupported full extensions. All newly added
forms retain the 040 fallback. Shared 030 execution is tested without enabling
another host CPU. Against the previous `.53` binary, 162 new cases fail on
missing forms and 27 fallback/full-extension controls pass.
