# Lemmings host-time profile — 2026-09-24

This is a diagnostic sampled profile of the current accepted stable Copper68k 1.4.1 package and frozen Lightweight engine. It does **not** report hardware performance-counter cycles, guest 68000 cycles, or a speedup. It samples managed host-thread time.

## Where the host time goes

The profile follows the Lemmings Kickstart 1.3 native replay through its scripted disk swap. In a seven-second interior sample of the main `ExecuteFrame` thread (154 interval slices), the broad exclusive groups were:

| Host-time group | Share |
|---|---:|
| Copper68k 68000 interpreter | 33.36% |
| `TickDevices` dispatch, including inlined device/video work | 29.75% |
| Other, including `SpanHelpers.Memmove` | 12.97% |
| Blitter | 7.65% |
| Bitplane fetch | 5.75% |
| Out-of-line video | 3.84% |
| Paula audio | 2.84% |
| Copper | 1.91% |
| Clock/bus wait methods | 0.98% |
| Sprites | 0.96% |

So the workload is split between guest CPU interpretation and device/video advancement. No single guest instruction routine accounts for most host time. `TickDevices` is a parent that includes inlined code, so its share is not just deadline comparisons. The `Other` group is mostly runtime `SpanHelpers.Memmove` (8.64% of the sample); its sampled stacks lead back to Copper68k branch/refill and prefetch paths, rather than to a display-buffer copy.

Within Copper68k, the largest exclusive method shares of the whole thread sample are `ExecuteSingleInstruction` **8.60%**, `BranchToAndRefillTarget` **5.71%**, `TopUpPrefetchOne` **3.85%**, `TopUpPrefetchAtRetirement` **3.67%**, `ExecuteInstructionBody` **3.35%**, and `TryExecutePlannedKind` **2.40%**. This points to interpreter dispatch and 68000 branch/prefetch servicing as the most visible CPU-core costs.

## Scope and evidence

The replay used the same accepted Lightweight engine hash as the package comparison and the current NuGet Copper68k 1.4.1 assembly. Its complete fingerprint matched the accepted identity and measured steady-state allocation was zero. The profiler ran at Normal priority on logical CPU 2 with sibling 3 protected, under .NET 10.0.12. The trace and analysis are local under ignored `artifacts/copper68k-package-benchmark/profile-current/`; [the machine-readable record](PROFILE_2026-09-24.json) contains build/input/tool hashes and the sampled method data.

Sampling and JIT inlining limit this result: it ranks large current costs, but small percentages are noisy and the 7-second profile must not be compared as a speedup against the older September 22 profile. No engine or CPU code changed and no performance acceptance measurement was made.
