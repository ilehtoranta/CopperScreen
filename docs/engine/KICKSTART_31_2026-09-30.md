# Native A500 Kickstart 3.1 — 2026-09-30

The Lightweight desktop now accepts native **A500 Kickstart 3.1, 512 KiB,
v40.63**, alongside Kickstart 1.3. The default 68000 boots Workbench 3.1 from
floppy with either zero or 2 MiB of Autoconfig Fast RAM. The
[manifest](KICKSTART_31_2026-09-30.json) records input identities, source hashes,
checks and captured output. Licensed inputs and raw captures remain local under
`artifacts/kickstart31-2026-09-30/`.

## Implementation and Legacy audit

The engine already accepted 512 KiB ROMs, mapped them at `$F80000` and exposed
their reset vectors through the low-memory overlay. Before this change, bounded
runner probes reached both the 3.1 insert-disk screen and Workbench desktop.
The desktop rejected every ROM except 256 KiB Kickstart 1.3.

The change enables the desktop boundary: ROM size/version/revision validation,
the explicit `Kickstart31Rom` source, profile loading/saving, availability and
Settings. Browse identifies the selected native ROM and selects its version;
multi-ROM ZIP selection follows the current Kickstart choice. Validation-cache
keys include the source and version so a selection change cannot reuse a stale
result. Other machine revisions, including v40.68 and v40.70, remain rejected.
Header checks select a supported ROM shape; they do not authenticate every byte
or replace a ROM checksum check.

The retained Legacy `AmigaBoot.TryActivateKickstartRomExecServices` reference
installs host Exec/device gateways after native startup. Lightweight executes
ROM and Workbench code directly. This implementation reuses the existing native
ROM mapping and adds no host OS services, CPU patch, instruction bypass or engine
timing change. Copper68k remains the pinned public `1.5.0` dependency.

The older `a500-kickstart31-host-exec` profile ID remains loadable for existing
references. Its display name and description now describe native Kickstart 3.1
with 2 MiB Fast RAM and two drives; the historical ID does not enable host Exec.

## Start the desktop

Select **Lightweight A500 + Kickstart 3.1**, supply an A500 v40.63 ROM and your
Workbench disk, then start. Alternatively, Browse on the Setup page detects a
supported 1.3/3.1 ROM and selects its Kickstart choice. Fast RAM is optional in
Settings > Memory.

```powershell
dotnet run --project CopperScreen -c Release -- --profile lightweight-a500-kickstart31 --rom "path/to/kickstart-3.1-a500.rom" "path/to/Workbench31.adf"
```

Captures at field 1 and every 1,000 fields include CPU/device JSON, full-beam BMP,
Chip/slow RAM and PCM, plus Fast RAM/mapping when fitted. The host also preserves
every native pixel in its presentation buffer. Final native pixel SHA-256 is
`aae907938c788bd6f3f29521d2f3fffccc5ee4db0acc0634b19bc024080dd84f`
for both Workbench configurations. The native tests bind exact ROM/ADF hashes,
final cycle/PC, overlay release, Fast RAM assignment and this reviewed desktop.
Synthetic fixtures cover profile/version persistence, reset and rejection paths;
they are separate from native boot evidence.

To repeat the optional native tests, provide the unmodified ROM and extracted
Workbench ADF whose hashes are in the manifest:

```powershell
$env:COPPERSCREEN_KICKSTART31_ROM = "path/to/kickstart-3.1-a500.rom"
$env:COPPERSCREEN_WORKBENCH31_ADF = "path/to/Workbench31.adf"
dotnet test CopperScreen.Lightweight.Tests/CopperScreen.Lightweight.Tests.csproj -c Release --filter FullyQualifiedName~SuppliedNativeWorkbench31Boots
```

Missing local files skip the optional replay. Different supplied bytes fail the
identity checks instead of being reported as the pinned replay.

## Limits

This is PAL OCS A500 boot evidence on the default 68000 with 512 KiB Chip and
512 KiB slow RAM. It does not establish a full Workbench installation, native
3.1 hard-disk persistence, application compatibility, accelerator/3.1 combinations,
ECS/AGA support or 68060 OS/FPU compatibility. The existing experimental CPU
choices retain their disclosed limits; 68060 remains unavailable in the desktop.
Broader ROM revisions and larger Chip RAM require separate validation.

These limits describe the original floppy-boot slice. The subsequent
[HD boot correction and evidence](KICKSTART_31_HD_2026-09-30.md) verifies native
3.1 FFS/RDB boot and persistence on the default 68000. The original manifest
remains a record of the earlier source and runs.

Runner FPS and allocations are diagnostic observations. No throughput acceptance
or change to historical measurement protocols is claimed.
