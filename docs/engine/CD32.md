# Experimental Lightweight CD32

CopperScreen can construct a stock PAL or NTSC CD32 with Alice/Lisa, 2 MiB Chip
RAM, a 68EC020 and no floppy drives. The experimental desktop launcher is
available while qualification against WinUAE 6.0.3 continues. The reference revision is
[`857f48fcb09399d4d95527e29a2fdeaedb41f827`](https://github.com/tonioni/WinUAE/commit/857f48fcb09399d4d95527e29a2fdeaedb41f827).
Board clocks and signals come from the
[Commodore CD32 schematic](https://www.amigawiki.org/dnl/schematics/CD32_R3.pdf).

## Running from the desktop

Choose **CD32 (Experimental)…** in the launcher. Select a combined 40.60 ROM or
the separate Kickstart and extended ROMs. Choose the ZIP directly in the
**CD32 disc** picker. If the ZIP contains several CUE sheets or standalone disc
images, choose the disc inside the archive. For Castlevania AGA Fast RAM, select
**PAL** and **8 MiB** Fast RAM.

**Mount CD…** and **Eject CD** change discs during a session. The existing
controller profile's primary and secondary fire controls map to Red and Blue.

## Running the diagnostic profile

```powershell
dotnet run --project CopperMod.Amiga.Lightweight.Runner -c Release -- --cd32 --video-standard ntsc --synthetic-rom-stop --frames 10
dotnet run --project CopperMod.Amiga.Lightweight.Runner -c Release -- --cd32 --rom cd32.rom --extended-rom cd32-ext.rom --cd disc.cue --nvram cd32.nvr --boot-probe artifacts/cd32-replay --frames 600
```

PAL is the default. The ROM loader recognizes the original 40.60 Kickstart and
extended ROM banks using the
[reference ROM identities](https://github.com/tonioni/WinUAE/blob/857f48fcb09399d4d95527e29a2fdeaedb41f827/rommgr.cpp).
Use `--rom` alone for a combined image or for the recognized physical dump.
`--fast-ram-kib 8192` fits an 8 MiB Zorro II Fast RAM board. Fast RAM defaults
to zero for the stock console.
Persistent NVRAM is a raw 1 KiB file. The runner replaces its contents atomically
on exit after a completed guest write.

The disc reader supports Mode 1 ISO and raw BIN/IMG. CUE sheets can reference
multiple files with MODE1/2048, MODE1/2352 and AUDIO tracks, file-relative
INDEX 00/01, and silent PREGAP sectors. WAVE audio uses 44.1 kHz stereo 16-bit
PCM. The CD layout counts complete sectors, matching WinUAE when a WAV track
ends partway through a sector. MP3 audio supports 44.1 and 48 kHz mono or stereo
and is decoded to CD audio sectors on the worker. CD audio plays through the
existing stereo output.
Mount a `.zip` directly when it contains one CUE sheet or one standalone data
image. With multiple discs, select an entry using `archive.zip#/path/to/disc.cue`.
Keep companion tracks in the archive at their CUE-relative paths. The emulator
uses temporary seekable files for the mounted disc and cleans them up on eject,
replacement, or shutdown.
`--cd-turbo` shortens data read delays. The runner's
input script accepts `cdPath` or `ejectCd` for media changes during a boot probe.
Use `cd32ButtonsPort0` or `cd32ButtonsPort1` to attach a pad and send a numeric
mask. Play, Reverse, Forward, Green, Yellow, Blue and Red use bits 0 through 6.
Joystick directions use the existing input fields.

Akiko access widths, packet checksums, ring comparators, prioritization of
data blocks and subchannel buffer layout were implemented against the
[Akiko reference](https://github.com/tonioni/WinUAE/blob/857f48fcb09399d4d95527e29a2fdeaedb41f827/akiko.cpp).
File reads and Mode 1 sector encoding run on a worker. Bus transfers, interrupt
assertion, CD playback position and PCM mix run on the execution owner. Akiko
addresses Chip RAM and guest-configured Zorro II RAM and uses available CCKs
after the existing chipset owners and before CPU grants. The exact drive seek,
DMA arbitration, controller analog timing, CD audio DAC and CIA TOD phases
still require native and hardware evidence.

The supplied Dangerous Streets and Disposable Hero ZIPs contain ADF floppy
dumps for separate floppy or AGA compatibility comparisons. Native CD32
qualification also requires original disc images and the ROMs and media for
the optional variants. Keep those files out of the repository. Record source
identities, fixture hashes, guest input and observable WinUAE checkpoints in
the replay evidence before counting a row as passed. Synthetic runner rates

## Sqrxz boot timing

The 2026-11-24 comparison used the verified Amiga Forever 40.60 ROM pair
and the [developer's Sqrxz ISO](https://www.sqrxz.de/sqrxz/), SHA-256
`F3ECFD7F9D8840EE80F59E8EEE3DEE757E3F6E8498B6CD2C9480A3AFE030C988`.
Stock PAL WinUAE 6.0.3 read the CDTV trademark, read the sectors containing
`S/Startup-Sequence` and reached the Sqrxz v1.2 title screen. Its trace
showed no guest reset during that boot.

At `7670f53`, the ROM sent EEPROM control byte `$A0` and lowered SCL
while releasing SDA with a single long write to `$B80030`. Processing the
direction lane first exposed a transient STOP on the I²C bus. The firmware
missed the acknowledgement, abandoned the nonvolatile-memory access, and
polled the CD before its table of contents was ready. It started the console
animation, recognized `CDTV.TM` later, and called `ColdReboot` at `$E00552`.
Accelerating TOC delivery to 2.2 ms per packet masked that EEPROM failure.

Akiko now presents both EEPROM pin changes in the same strobe. With the stock
TOC cadence, the ROM took the direct boot branch at `$E00558` in PAL field
500 and NTSC field 594. Both read `S/Startup-Sequence` at LBA 343
and rendered the Sqrxz v1.2 title
by field 1,425. The empty-drive PAL control showed the CD32 logo at field
1,100. Instruction timing still differs earlier in the boot. In a PAL
WinUAE run with diagnostic ROM markers, the Kickstart checksum loop ended
in field 22. CopperScreen reached the same instruction in field 33.

## Skeleton Krew

The 2026-11-24 replay used the verified Amiga Forever 40.60 ROM pair and the
[TOSEC CD32 dump](https://archive.org/details/Amiga_CD32_TOSEC_2009_04_18).
The title archive has SHA-256
`43A6AACEC0ADED6D9AEAB5F8DB8E6AFDA929FB411BF795E5352B8BA86596FB6F`.
Mount the extracted CUE with the companion ISO and six WAV files together.
WinUAE 6.0.3 reports the first audio track at LBA 2723 and lead-out at
127891. The previous CopperScreen reader rejected the CUE at MODE1/2048.

The seven-track disc reaches the title menu on both stock console profiles.
Five captured PAL fields each contain a sequence of 120 consecutive stereo
samples from WAV track 2, after accounting for the held samples added by
resampling. The baseline ISO-only replay produces silence at the title.

On PAL, Red at field 1930 entered the single-player menu and Blue at
field 2500 confirmed Joint in the CopperScreen replay. Scripted right and
down inputs moved the player and scrolled the opening Monstrocity area.
Red produced visible shots.

The initial gameplay capture had 128 populated display rows alternating with
128 black rows. The game sets `DDFSTRT=$0010`, before Alice's horizontal
hard start at `$18`. The OCS-style start permit skipped every second row.
The AGA path now retains the early comparison until the hard limit releases.
The corrected field 3300 contains all 256 display rows.

The next comparison found that the left HUD and playfield had different
horizontal alignment. Lisa's `BPLCON1` controls odd and even reloads at 35 ns
granularity. CopperScreen had discarded the fractional part at lower display
resolutions. The shifters now retain each parity's phase through composition.
Lisa's border blank signal also leads the display window by one sample,
which accounts for the former difference at the right edge.

The aligned opening captures from CopperScreen and WinUAE 6.0.3 now match
all 327680 RGB samples at SuperHires horizontal resolution. A PAL replay
through field 4050 exercised right, down, left and up inputs. Captures
every 25 fields show the camera following the player, terrain continuing
across bitplane pointer and fine-scroll changes, and the HUD staying fixed.
WinUAE captures show the same camera response to those directions.

The standalone Sqrxz ISO replay retained its CPU, hardware and output
fingerprints through 1500 PAL fields and matched all six captured frames.

## Alien 3 CD32 Edition

The 2026-11-24 replay used Mister_Grave's CD32 release from GameBase Amiga 97.1.
[Release thread](https://eab.abime.net/showthread.php?t=124171),
[GameBase archive](https://archive.org/details/commodore-amiga-update-97.1.7z).

The Alien 3 ZIP has SHA-256
`6C7E5E03723831AC229FB7E86DA751CBDB5AB5413FB77FF5580BBA322E308F31`.
Mount the CUE alongside its ISO and 24 WAV files. Seven tracks have short
PCM tails. Counting complete sectors places the first audio track at
LBA 68557 and lead-out at LBA 260229. All 25 track starts and track types
match WinUAE 6.0.3.

On stock PAL with the Amiga Forever 40.60 ROM pair and normal drive timing,
the game played the HAM8 intro, accepted Red to skip it, showed the title
and entered level 1 by field 4200. Scripted inputs scrolled the level,
jumped, fired, changed weapon, and paused and resumed the timer. Captured
PCM matched WAV track 6 at the title and track 4 during gameplay. The
ISO-only control reached the same opening area with silent CD music.

On stock NTSC the same disc displayed the intro and entered level 1 by
field 5300. Captured PCM matched the same title and gameplay WAV tracks.

The opening comparison at `52d8d63` captured WinUAE 6.0.3 through its native
screenshot command on both stock video standards. CopperScreen fields 4200
(PAL) and 5350 (NTSC) were aligned to WinUAE fields 4735 and 5517 at the spawn
point. The captures show different timer and animation states. After removing
WinUAE's line doubling, 125204 of 128740 PAL foreground samples and 124100 of
127548 NTSC foreground samples match exactly in the common area. The sampled
SCORE and ENERGY label regions match all 1496 foreground samples on each
standard. Both emulators render the blue radar on PAL and the yellow radar
and muted player palette on NTSC. This establishes the observed color change
in the reference emulator. Physical hardware and field-aligned parity remain
unverified.

WinUAE requested the same title and gameplay tracks at LBAs 98201 and 76301.
Its host audio device failed to initialize. The CopperScreen NTSC intro
samples included stretches of silence. Intro PCM parity remains open.

## Castlevania AGA

The 2026-11-24 replay used the [developer's Fast RAM CD32 release](https://www.mediafire.com/file/osemoc30rnxt0v0/CastlevaniaAGA_CD32_ISO_FASTRAM.zip/file)
with SHA-256 `AA705B73858F12220D2B5F3BAD253D4804B51492257C7E2A3495FE7BE519C3C6`.
Mount the ZIP directly. For a loose mount, keep the supplied CUE beside the ISO
and all 13 MP3 tracks. The PAL profile used 2 MiB Chip RAM, 8 MiB Zorro II Fast
RAM at `$200000`, the verified Amiga Forever 40.60 ROM pair and normal drive
speed.

With Fast RAM fitted, the ROM placed Akiko's command and response rings at
`$9FFC00` and the sector buffer at `$210000`. Masking these addresses to Chip
RAM corrupted the command packets and prevented the ROM from reading sectors.
Akiko now accesses the configured RAM bank at those addresses.

CopperScreen and WinUAE 6.0.3 reached the title and selected CD audio track 7.
CopperScreen placed that track at LBA 75356 using the MP3s' decoded durations
at their source rates. WinUAE reported LBA 81972. In CopperScreen, the captured
field 1725 contained 883 consecutive stereo samples from the 48 kHz source
after CD DAC resampling and duplicate output samples were accounted for.

With a CD32 pad on Port 2, Blue at field 1905 started the game. Stage 01 was
visible by field 2300. Scripted directions, Red and Blue exercised movement,
the whip and jumping. Track 11 played during the opening area. The replay
ended in Stage 01 at field 3250.

Mounting the original ZIP reproduced the loose CUE replay's video and PCM
captures byte for byte at field 1800 (title) and field 2400 (Stage 01).
The runner removed its temporary disc files on exit.
The Windows desktop picker also opened the original ZIP with this profile.
The desktop reached the title and opening story, then ejected and remounted
the archive from the CD32 controls.

WinUAE's data-ISO control showed the parallax sky across the full playfield.
CopperScreen originally drew only its left section. In Stage 01 the guest sets
SSCAN2 and supplies the sprite strips at positions that repeat when Lisa ignores
SH10. The corrected comparator matches both horizontal positions, as described
by the [Lisa specification](https://www.amigawiki.org/lib/exe/fetch.php?media=de%3Aparts%3Aaa_lisa_specification.pdf)
and implemented in [WinUAE's Denise renderer](https://github.com/tonioni/WinUAE/blob/857f48fcb09399d4d95527e29a2fdeaedb41f827/drawing.cpp).
The CUE replay now shows the sky across the playfield while idle and scrolling.
The current Alice DDF start handling also renders the attract sequence's full
castle text. Later stages and timing parity remain unqualified.
