# True Fast RAM — 2026-09-27

Lightweight now supports optional **512 KiB, 1, 2, 4 or 8 MiB of CPU-only Zorro II
Fast RAM**, alongside the existing 512 KiB Chip and 512 KiB slow RAM. The default
remains zero Fast RAM. The desktop Memory page, saved profiles, restart flow and
runner `--fast-ram-kib` option expose the same sizes.

The [manifest](FAST_RAM_2026-09-27.json) binds source, package, ROM/media identities,
tests and native captures. Raw outputs are local under
`artifacts/fast-ram-2026-09-27/`; no ROM, operating-system or game bytes are added
to the repository.

## Memory and Autoconfig contract

The board follows Commodore's [Autoconfig register specification](https://amigadev.elowar.com/read/ADCD_2.1/Hardware_Manual_guide/node02C8.html)
and the [A500 technical reference](https://erikarn.github.io/amiga/docs/Amiga_500_Technical_Reference.pdf).
Its Zorro II type advertises the standard size code, memory-list bit and preferred
8 MiB expansion window. It retains Copper's virtual RAM identity `$07DB/$49`.
Identity nibbles use the existing chain's inversion rules. The memory board is
first, followed by optional CopperHDF; mapping or shut-up advances the chain.

Kickstart writes the assignment through `$E80048/$E8004A` and registers the RAM
with Exec. No host code inserts a memory header or patches Kickstart. The complete
bank must fit within `$200000–$9FFFFF`; this virtual board accepts 64 KiB address
granularity. Native Kickstart 1.3 assigns **all five sizes at `$200000`**, including
4 MiB. An initial overly strict size-alignment check rejected that 4 MiB assignment;
the failed capture remains recorded separately from the corrected runs.

Before assignment and after shut-up/reset, the bank is unmapped. Both machine
reset and guest RESET clear board assignments and reopen Autoconfig while
retaining RAM bytes. A new machine allocates fresh zeroed storage. The public
`FastRam` view is read-only and `FastRamBase` is nullable until configured.

CPU accesses use the existing non-Agnus path: no refresh, display or blitter wait
is added. The CPU core and 020 bridge retain their transfer clocks on the single
machine timeline. This is a **16-bit Zorro II bank**, not 32-bit accelerator-local
RAM. Chipset DMA helpers still mask into the fitted Chip RAM array. Code peeks
and CopperHDF guest-buffer validation include only the configured RAM range.
This does not establish electrical Zorro timing or host throughput acceptance.

## CPU dependency

Native 020 Autoconfig first stopped on `$41FB` at `$FC4FC2`, an unsupported
PC-relative brief-indexed `LEA`. The correction belongs to Copper68k, not the
memory bus. Owner commit `7702705` adds that operand form and 99 focused cases for
020, EC020 and shared 030 execution: extension-word PC base, signed word/long
index, scaling, register aliasing, unchanged flags and explicit rejection of
unsupported full extensions. The existing indexed-LEA timing policy is reused;
the 040 path keeps its fallback. No additional CPU model is enabled.

CopperScreen pins **local, unpublished `Copper68k 1.4.2-ocs020.53`**. The preceding
`.52` remains the published prerelease. The new source patch and package are
retained locally; a clean checkout requires this exact candidate in the local
feed until an explicit release. No publication or push was performed here.
The initial build also exposed an old cached `.52` package. Its cache was archived
and refreshed from the published artifact, without weakening hash validation.

The original Lotus media and input script are unchanged. At the final enabled-RAM
checkpoint, 68000 displays car selection and 68020 displays the options menu.
Different hardware configurations need not consume fixed-time inputs identically;
these runs do not establish player-controlled racing or complete game compatibility.

The native 68000 allocation/I/O fixture boots an existing supplied Workbench 1.3
OFS partition through CopperHDF with 2 MiB Fast RAM. Its disposable startup runs
`AddBuffers SYS: 1200`, `Avail`, and writes/reads `fast-proof.txt`. The final capture
shows the expected proof text and `FAST RAM NATIVE TEST FINISHED`. The new bank's
free bytes fall from 2,097,120 to **1,903,456**; Exec memory headers and free lists
remain consistent. An independent OFS reader verifies the 39-byte persisted file,
directory/data-chain structure and checksums. Engine tests additionally transfer
whole sectors with the request, unit and data buffer all in Fast RAM, and reject
a buffer crossing the bank boundary before transfer.

The [probe tools](../../scripts/probes/FastRam/README.md) reproduce memory-list
inspection and prepare disposable native media. They do not distribute ROM/OS
content. Snapshots add `.fastram` and `.memory.json` only when RAM is installed;
disabled-feature captures retain their existing schema and bytes.

## Remaining limits

At the end of this initial slice, an extra 020 CopperHDF boot check stopped on
indexed `JSR` `$4EB2` at `$FC4E28`, also with Fast RAM disabled. The native
allocation/write proof above uses 68000. The subsequent
[020 CopperHDF correction](COPPERHDF_020_2026-09-27.md) resolves that blocker and
the later reached operand gaps in local CPU `.54`, with 020/EC020 allocation and
OFS write/read proofs. The original `.53` results and manifest here are retained.
Broader game compatibility, 030/040/060, Zorro III, accelerator-local 32-bit RAM,
larger Chip/slow configurations and physical timing remain separate work.
Desktop settings persistence/restart is covered by host tests; no manual desktop
interaction or formal throughput measurement is claimed. No golden was updated.
